## 2023-10-25 - Secure Server Actions

**Vulnerability:** Next.js Server Actions directly performed database operations using unchecked inputs and lacked error handling, causing internal error strings to be exposed or allowing invalid types (e.g. string when number expected) leading to TypeErrors and application crash.
**Learning:** Server Actions expose endpoints. Any user input through form data directly invokes these functions. We must strictly validate all input parameters for types, boundaries (negative amounts, overflows), lengths (prevent unbounded strings). And we must wrap DB operations in `try/catch` using generic return errors without leaking exceptions. Also, returning objects from forms in React 19 triggers type errors requiring inline async void functions in the action prop.
**Prevention:** Always implement boundary and type checks at the top of Server Actions, even if types seem constrained by form inputs. Use `try/catch` and return generic strings like `{ error: 'An error occurred' }`. Use parameterless `catch { ... }` in TS to avoid unused variable errors. When using server actions returning objects, wrap them in async `() => { ... }` returning void on the frontend.
