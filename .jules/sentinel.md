## 2024-05-15 - Missing Input Validation and Secure Error Handling in Next.js Server Actions
**Vulnerability:** Server Actions lacked input validation (type, bounds, length) and secure error handling (`try/catch`). Malicious input could cause unhandled exceptions that might leak internal stack traces or database schema details to the client.
**Learning:** Next.js Server Actions act as direct API endpoints and must validate all inputs natively and catch any internal errors to prevent leaking sensitive information to the client. When catching errors in TypeScript and returning generic messages, use parameterless catch (`catch { ... }`) to avoid unused variable warnings. Also, returning an object from a Server Action called directly in a React 19 `<form action={...}>` causes a TypeScript error; it should be wrapped in an inline async function returning `void`.
**Prevention:** Always apply strict validation (checking existence, type, bounds, length) at the beginning of Server Actions. Wrap the database and logic operations in `try/catch` blocks that return generic user-friendly error messages.
