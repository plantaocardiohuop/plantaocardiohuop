## 2024-10-31 - Missing Server Action Input Validation and Raw Error Exposure
**Vulnerability:** Server Actions in `src/app/actions.ts` directly used input without explicit type, length, or boundary validation (e.g., `memberId <= 0` or NaN checking before querying the database) and exposed potentially sensitive database errors by not wrapping transactions in `try/catch` blocks.
**Learning:** In Next.js, Server Actions are public endpoints by default. Relying solely on TypeScript typings during compilation does not protect against malicious runtime payloads or database injection patterns when parameters like strings or numeric IDs are passed unchecked. Additionally, raw database error bubbling could expose internals. Furthermore, in Next 19, when Server Actions are modified to return objects (like `{ error: 'msg' }`) directly inside forms, it causes a Type Error. This must be bypassed by wrapping the action in an inline async void function `action={async (formData) => { 'use server'; await actionName(formData); }}`.
**Prevention:** Always validate all input parameter types, lengths, and logical bounds at the beginning of Server Actions. Always wrap Prisma database operations in a `try/catch` block and return standardized, non-descriptive error messages. Wrap server actions returning objects inside forms with inline async functions returning void.
