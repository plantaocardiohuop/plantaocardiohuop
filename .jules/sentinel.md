## 2024-10-13 - Missing Server Action Input Validation and Error Handling
**Vulnerability:** Next.js Server Actions (`addMember`, `recordAttendance`, `addBonusPoints`, `deleteMember`) directly accessed the Prisma database without validating input types, lengths, or bounds, and lacked try/catch blocks. This could lead to Denial of Service (DoS) via excessively long inputs, crashes from unexpected types, and potential information leakage if raw database errors were returned to the client.
**Learning:** Next.js Server Actions execute on the server but are invoked directly by the client. They must be treated like API endpoints and robustly validate all inputs while failing securely with generic error messages.
**Prevention:** Always validate the type, length, and bounds of arguments passed to Server Actions before using them in database queries. Wrap database operations in try/catch blocks and return standardized, user-friendly error messages instead of raw error objects.
