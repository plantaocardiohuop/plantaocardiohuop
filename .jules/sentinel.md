## 2024-05-24 - Unvalidated and Information-Leaking Server Actions
**Vulnerability:** Next.js Server Actions were accepting input without type checking, length bounds, or sanitization, which could lead to malformed data in the database or potential DoS via excessively large inputs. Additionally, they were lacking try/catch blocks, meaning any database errors or internal exceptions would bubble up to the client, potentially exposing database schema or internal application state details. Finally, the server actions do not use an explicit authentication check inside them.
**Learning:** Next.js Server Actions can bypass route-level middleware and act as public API endpoints. Thus, any function exported with `'use server'` must validate all parameters strictly and wrap operations in `try/catch` blocks that return generic error messages to avoid information leakage. When a server action returns an object in React 19, an inline async wrapper is needed in the `action` attribute to prevent TypeScript errors.
**Prevention:** Always implement explicit input validation, length bounds checking, and generic error handling in Server Actions. Never assume the caller is the legitimate front-end application. Always add explicit authentication/authorization checks inside the server action functions themselves (though this repo currently lacks an auth system to integrate with).
