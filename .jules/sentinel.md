## 2023-10-25 - Prevent Database Details Leakage in Server Actions
**Vulnerability:** Next.js Server Actions were implemented without `try/catch` blocks or input constraints. If a database query failed (e.g., due to an invalid input type or unique constraint violation), the raw error details (including stack traces or database schema information) could potentially leak to the client. Additionally, the lack of input boundaries could expose the database to excessively long inputs, increasing DoS risks or database strain.
**Learning:** Next.js Server Actions are public endpoints by default. Even when called internally, untrusted data can be sent to them. Relying solely on HTML form attributes (like `required` or `type="number"`) is insufficient because they can be easily bypassed by attackers invoking the action directly or modifying the payload.
**Prevention:** Always validate and sanitize all inputs at the beginning of a server action (e.g., check types, lengths, and bounds). Wrap database interactions and sensitive logic in `try/catch` blocks to securely catch errors, and always return a generic, user-friendly error object rather than rethrowing or exposing internal error details. Furthermore, returning an error object requires wrapping the server action in an inline async function in React 19 to satisfy TypeScript.
