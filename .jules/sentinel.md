## 2023-10-16 - [HIGH] Fix Server Action Input Validation and Error Handling
**Vulnerability:** Next.js Server Actions (`addMember`, `recordAttendance`, `addBonusPoints`, `deleteMember`) in `src/app/actions.ts` lacked robust input validation (type checking, length bounds, NaN checks) and error handling. They implicitly trusted client inputs and let Prisma directly process the data. This could lead to Unhandled Exceptions, Potential Denial of Service (large strings/numbers), or Database issues.
**Learning:** Next.js Server Actions are public API endpoints when exported from `'use server'`. They are susceptible to the same vulnerabilities as traditional REST APIs. They must not assume client inputs are safe or valid simply because the UI restricts them. Furthermore, uncaught exceptions from database operations (like Prisma) can leak sensitive internal logic or state.
**Prevention:** Always validate all inputs (type, bounds, length, structure) at the very beginning of every Server Action. Wrap the entire server action logic in a `try/catch` block. Ensure the `catch` block returns a generic, safe error message to the client, preventing internal errors or stack traces from bleeding out.
